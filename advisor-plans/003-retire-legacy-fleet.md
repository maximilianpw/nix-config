## Why this matters

Production Home Manager already installs the standalone Rust Fleet package, but this repository still renders, packages, and tests the retired Bash CLI. The old code is roughly 1,000 lines of Bash plus hundreds of lines of migration assertions and fixtures. The pinned Fleet source already includes Rust tests for SSH planning, forwards, launchd tunnel state, doctor deadlines, child ownership, and signal cleanup; retaining the old oracle now duplicates ownership and can hide Rust regressions because the integration check is not selected by normal regression CI.

## Current state

- `modules/fleet/home-manager.nix:65-71` installs the Rust input:

```nix
programs.fleet = {
  enable = true;
  package = inputs.fleet.packages.${pkgs.stdenv.hostPlatform.system}.fleet;
  inherit (fleet) settings;
};
```

- `lib/fleet.nix` still exposes a candidate hook and legacy package:

```nix
candidatePackage ? null,
...
legacyPackage = pkgs.writeShellApplication {
  name = "fleet";
  ...
  text = fleetScript;
};
package = if candidatePackage == null then legacyPackage else candidatePackage;
```

- `lib/fleet.nix` reads `scripts/fleet.sh`, `scripts/fleet-tunnels.sh`, and `scripts/fleet-tunnel-runner.sh` to construct the old implementation and launchd jobs.
- Production consumers need only these Nix-projected values from `lib/fleet.nix`: `files`, `settings`, `sshSettings`, and `aliases`. Launchd agents are generated by the external Home Manager module from `settings`.
- `tests/fleet-rust-integration.nix` compares the external module against the legacy implementation and asserts that the default remains Bash. Those migration assertions are now obsolete.
- `tests/fleet-installed-regression.nix` checks the actual Kim/Joyce configurations use the pinned Rust package and validates generated TOML. This check should remain.
- At planning time, the pinned Fleet source resolved to `/nix/store/qs6qzyr3q1ga3b3mfcasi4fwj6qznc9g-source`. Its `nix/package.nix` uses `rustPlatform.buildRustPackage`, so package builds run the Rust test suite. Tests include:
  - `tests/ssh.rs`: SSH, tmux, run, forwarding, aliases, safety, and binary fake-command tests;
  - `tests/tunnels.rs`: launchd state, pause/resume, ownership, doctor outcomes, and short injectable deadlines;
  - `tests/runner.rs`: startup deadlines, child ownership, signals, and listener behavior;
  - `tests/config.rs`: configuration parsing/validation.
- `scripts/ci/build-regression-checks.sh` selects only check names ending in `-regression`; `fleet-rust-integration` is therefore skipped.

Repository boundary: `nix-config` owns personal inventory, SSH settings, known hosts, and generated `FLEET.md`; the standalone Fleet flake owns the runtime CLI and launchd module.
