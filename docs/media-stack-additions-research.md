## Caveats that affect the assessment

Chaptarr's repository dates to [2026-06-29](https://api.github.com/repos/Chaptarr/chaptarr), so its star count has had about three months to grow. All seven published GitHub releases are [prereleases](https://api.github.com/repos/Chaptarr/chaptarr/releases?per_page=100). Its README calls it beta, says Docker is the only supported installation, and reports over 11,000 active users. That user count is the project's claim and was not independently verified. [Chaptarr README](https://github.com/Chaptarr/chaptarr#readme)

Tdarr's main repository is its public project, packaging, and issue-tracking repository. The software uses a proprietary EULA, and the repository does not expose the core implementation. Its 4,338 stars should not be confused with the separate [Tdarr_Plugins repository's 226 stars](https://api.github.com/repos/HaveAGitGat/Tdarr_Plugins). The public plugins have human fixes, and current application versions come from the official distribution manifest and packaging metadata. Its [GitHub releases](https://api.github.com/repos/HaveAGitGat/Tdarr/releases?per_page=100) stop at a 2020 beta and do not represent current Tdarr 2.x releases. [Repository contents](https://api.github.com/repos/HaveAGitGat/Tdarr/contents), [license](https://github.com/HaveAGitGat/Tdarr/blob/master/LICENSE.md), [official versions](https://storage.tdarr.io/versions.json)

cross-seed's repository reports a push on 2026-09-13, but its default `master` branch's newest commit and the newest merged pull request found are from 2026-06-15. Its `nightly` branch is older still, with a newest commit on 2026-01-04. The repository contains dependency-bot branches, so a recent repository push alone does not establish new application work. This is a quiet period of roughly three and a half months on the default branch, not proof of abandonment. [Repository API](https://api.github.com/repos/cross-seed/cross-seed), [master commits](https://api.github.com/repos/cross-seed/cross-seed/commits?sha=master&per_page=5), [nightly commits](https://api.github.com/repos/cross-seed/cross-seed/commits?sha=nightly&per_page=5), [recent closed pull requests](https://api.github.com/repos/cross-seed/cross-seed/pulls?state=closed&sort=updated&direction=desc&per_page=30)

Maintainerr now supports Plex, Jellyfin, and Emby. The project recommends separate instances for separate media servers, each with isolated rules, collections, and data. Tautulli is Plex-only. [Maintainerr README](https://github.com/Maintainerr/Maintainerr#features), [Tautulli README](https://github.com/Tautulli/Tautulli#readme)

## Assessment

Recyclarr, Unpackerr, Maintainerr, Tautulli, Kometa, and autobrr show recent substantive human maintenance as well as recent stable releases. Each is a reasonable candidate if its function is needed. Tdarr also has current releases and plugin maintenance, with less visibility into core development because its source is closed.

Chaptarr looks actively maintained, but its beta status and short public history make a trial more appropriate than treating it as an established replacement. cross-seed has an existing audience and usable stable release, but its quieter recent history deserves more caution than autobrr's frequent fixes. These assessments concern adoption and maintenance; they do not establish reliability, security, resource use, or value for a particular library.

The checks sampled up to 100 default-branch commits and 100 releases per repository, plus recent closed pull requests where needed. Dependency-bot commits and automated release commits were separated from human fixes. No services were installed or activated.

My first recommendation is Navidrome if a dedicated music experience would improve on the current Plex/Jellyfin players. Music Assistant is most useful when the goal is home speakers and mixed music sources. Neither replaces Lidarr's acquisition role; both play music obtained or supplied elsewhere. That distinction is an assessment based on their documented functions.

beets is useful when tags, artwork, or duplicates need work. Its importer can copy, move, and rewrite files, so integrating it with a Lidarr-managed library needs an explicit ownership decision. The documentation also supports importing in place with tag writes disabled. [beets import modes](https://beets.readthedocs.io/en/stable/guides/main.html#basic-configuration)

ListenBrainz is best considered an integration with its hosted service for this stack. Self-hosting its server would add several backend components and is a larger undertaking than enabling a player's scrobbler. Its listening records are public, and the project's README distinguishes development setup from production installation. [ListenBrainz documentation](https://listenbrainz.readthedocs.io/en/latest/), [server README](https://github.com/metabrainz/listenbrainz-server#readme)

## Music discovery

Checked on 2026-09-30. With a 1,000-star minimum, the strongest dedicated discovery candidate reviewed is [Kima Hub](https://github.com/Chevron7Locked/kima-hub), formerly `Chevron7Locked/Lidify`. The old repository URL redirects to Kima Hub, whose live API reports [1,280 stars and no archive flag](https://api.github.com/repos/Chevron7Locked/kima-hub). Its latest stable release is [v1.10.0, 2026-08-24](https://github.com/Chevron7Locked/kima-hub/releases/tag/v1.10.0), and a [human playlist usability fix landed the same day](https://github.com/Chevron7Locked/kima-hub/commit/047e4726e3229effa9d5e1907cbe286b26685d53).

Kima's README documents similar-artist recommendations from Last.fm, discovery search with Deezer track previews, and download requests through Lidarr. Its Discover Weekly creates recommendations based on listening habits and requires Lidarr. It also supports playlist imports and audio-similarity exploration of the existing library. These are documented capabilities, not behavior tested in this repository. [Kima features and integrations](https://github.com/Chevron7Locked/kima-hub#readme)

It is a larger application than a simple discovery dashboard. Its documented components include PostgreSQL and Redis, and optional CLAP audio analysis needs 2–4 GB RAM per worker; GPU acceleration is optional. This makes it a candidate to evaluate separately, rather than an automatic addition to the existing stack. [Kima architecture and analysis requirements](https://github.com/Chevron7Locked/kima-hub#readme)
